--- Dashboard ---
1. The maintenance calories indicator shows 2/10 days logged when the user has logged only for yesterday and today.  This is a problem because the regression algorithm does not include today in its calculation.  This will mislead the user into believing they're closer to the regression algorithm kicking in than they actually are.  We need to align this widget with the requirements of the regression algorithm.
2. The calories consumed sparkline should include the current day.

--- Food Logging ---
1. When logging or editing a log entry, if a quantity is a whole number, it should default to being formatted as an integer in the entry field.  For example, currently, if there is a food item with a serving size of 100 grams, when the user goes to log that food item, the default value in the quantity field is "100.0".  Its just a little bit of extra friction for our users to constantly have to delete the trailing ".0".  Again, this fix should apply to logging and editing, for both foods AND recipes.  We shouldn't change the internal data model though, they should still be represented internally as floats.

--- Bodyweight Logging ---
1. On the bodyweight tab, we should remove the "+ Log weight" button in the top bar and move it to the bottom right, similar to the floating "+" button on the log screen.  This will improve design language consistency.

--- Goals ---
1. On the goals tab, the language on the "Per lb bodyweight" toggle option should change to "Per kg bodyweight" when the user switches from imperial to metric, or if the user is already using metric.  Just a verbage change, no code update needed here.
