- when the user logs a new food, and then adds a recipe, that new food doesn't appear among recent foods in the recipe add ingredient screen until the app is restarted.

- after adding an ingredient to a recipe, the displayed line item looks a little strange.  I added 100g of white rice, and it says:
  White Rice
  100.00 x 1 portion (46g) - 370 kcal

  The calculated calories are correct, but it should simply display as 100g.  This is because the entry for the serving size of white rice from openfoodfacts is formatted oddly and inconsistently.  we already have some robust logic for dealing with that in the logging logic, so we need to intelligently apply that to format it properly here.

- the individual lines representing logged foods on the history tab should include the quantity and unit logged

- we need to add a way to edit recipes

- we need to add a way to duplicate recipes

- on all food search screens, "create custom food" should always appear before the list of recent foods

- when adding a custom food, the calculated calories should re-calculate each time one of the macros are edited.  the user should still be able to edit the calories directly after the fact, but subsequent changes to the macros should re-calculate the calories and overwrite that.  this should only happen when the macro fields are manually edited

- deleting a logged food should be possible only from the history tab, not from the recently logged foods in the food search view

- the recently logged foods should be unique.  Currently logging the same food twice results in two entries in the recently logged foods list.  This is unnecessary as they're simply there to give the user a quick way to log a food that they've already eaten again

- actually, food searching needs to be reworked.  Currently searching always calls the openfoodfacts API, with no way of searching locally stored foods.  When searching, there should be a toggle between "My Foods" and "Search the Web".  When toggled to my foods, it should only search locally stored foods, and when it's set to search the web, it should call the openfoodfacts API.  It should be toggled to "my foods" by default, and the foods should appear sorted in order of recency.  this prevents the need for specific "recent foods" logic.  the create custom food button should only exist when toggled to "my foods", and it should still always appear before the list, whether or not the list is being filtered/searched

- the data model for foods needs to be updated with an optional field for brand.  We should populate it when saving a food from openfoodfacts

- when editing a logged food on the history screen, the user should only be able to edit the quantity, not the individual macros

- if the user forgets to log their weight, we should assume the same weight on all subsequent days until the next time they log it.  we shouldn't prevent the regression algorithm from kicking in just because they missed the odd day of bodyweight logging.

- during onboarding imperial should be selected by default

- the log screen and the history screen should be combined into a single new tab called "log".  there should be a button at the bottom with "log new food" that should bring you to the existing food logging flow.  primarily it should display logged food history.  it should only display a single day at a time, with "Today" being the default.  the user should be able to tap left/right buttons to go forward and backward in time.  logged food on this screen should be sorted in meal order (breakfast first, then lunch, then dinner, then snack at the bottom)
